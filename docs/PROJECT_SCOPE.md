# ขอบเขตของงาน: AI Pill Anomaly Detection

## วัตถุประสงค์

สร้างระบบต้นแบบที่ตรวจจับและระบุตำแหน่งตำหนิของยาเม็ด โดยเทรนจากภาพยาปกติเท่านั้น

งานนี้เป็นงานวิจัยต้นแบบ ไม่ใช่ระบบรับรองคุณภาพยาจริง

## สิ่งที่อยู่ในขอบเขต

- ขอบเขตงานคือยาเม็ด (tablet) ทุกรูปทรงและลักษณะ เช่น กลม รี แคปเล็ต สีต่าง ๆ หรือมีลายพิมพ์ โดยใช้ backbone ร่วมกัน และสร้าง memory bank กับ threshold แยกสำหรับยาเม็ดแต่ละชนิด จากภาพยาเม็ดปกติของชนิดนั้น
- ผลหลักทดสอบกับยาเม็ดจากชุดข้อมูล MVTec AD หมวด Pill ซึ่งมี mask ตำแหน่งตำหนิ การทดลองรอบ 2 เพิ่มยาเม็ดลักษณะที่สองจากชุดข้อมูล pillQC ซึ่งวัดได้เฉพาะระดับภาพ ยาเม็ดรูปทรงอื่นยังไม่มีผลทดสอบ
- การทดลองรอบ 2 ตรวจความน่าเชื่อถือของผลหลักด้วยหลาย seed และช่วงความเชื่อมั่น 95% และทดลองสร้าง memory bank จากภาพปกติจำนวนน้อย (few-shot) ด้วย PatchCore
- บอกว่ายาปกติหรือผิดปกติ และแสดงตำแหน่งที่ผิดปกติด้วย heatmap
- ใช้ PatchCore เป็นโมเดลหลัก และ PaDiM เป็น baseline
- วัดผลด้วย Image AUROC, Pixel AUROC, AU-PRO, Precision, Recall, F1 และเวลาต่อภาพ
- วิเคราะห์ผลแยกตามตำหนิ 7 ประเภท พร้อม false positive และ false negative
- ทำเว็บต้นแบบด้วย React และ FastAPI 4 หน้า ได้แก่ อัปโหลดภาพ ผลการตรวจ เปรียบเทียบโมเดล และผลการทดลอง ผู้ใช้เลือกชนิดยาได้ 2 ชนิด แต่ละชนิดใช้ memory bank และ threshold ของตัวเอง (รายละเอียดใน `docs/updates/2026-11-11_pill_type_selector/`)
- จัดทำรายงานและสไลด์นำเสนอ

## ส่วนต่อยอด

เว็บตรวจภาพที่มียาหลายเม็ดได้ เมื่อยาวางไม่ทับกันบนพื้นสีเข้ม ระบบแยกแต่ละเม็ดแล้วตรวจด้วยโมเดล PatchCore เดิม ยาเม็ดเดียวที่หมุน กลับหัว เปลี่ยนขนาด หรือไม่อยู่กลางภาพก็ใช้วิธีนี้เช่นกัน

ส่วนนี้ทดสอบบนภาพจำลองที่ตัดแปะจาก MVTec เท่านั้น จึงยังไม่ใช่ผลกับภาพถ่ายจริง

## สิ่งที่อยู่นอกขอบเขต

- จำแนกชนิดตำหนิอัตโนมัติ
- ยาที่ไม่ใช่ยาเม็ด เช่น แคปซูล หรือยาในแผง
- ใช้โมเดลเดียวตรวจยาเม็ดหลายชนิดรวมกัน
- ตรวจกองยาที่ซ้อนทับกัน หรือยาบนพื้นหลังสว่าง
- ตรวจแบบ real-time บนสายการผลิต
- ใช้งานจริงหรือรับรองคุณภาพยา
- ใช้เชิงพาณิชย์ เพราะ MVTec AD ใช้สัญญาอนุญาต CC BY-NC-SA 4.0
- ระบุชนิดยาอัตโนมัติ ผู้ใช้ต้องเลือกชนิดยาเองในเว็บ (MVTec Pill หรือ pillQC)

## กติกาการประเมินผล

- เทรนจากภาพยาปกติเท่านั้น
- ตั้ง threshold ที่เปอร์เซ็นไทล์ 99 ของคะแนนภาพปกติใน validation
- ล็อกโมเดลและ threshold ก่อนประเมินบน test
- ห้ามใช้ test เลือกหรือปรับโมเดล แล้วรายงานเป็นผลอิสระ
- การทดลองที่เลือกหลังเห็นผล test ต้องระบุว่าเป็น exploratory

## ผลการทดลองรอบ 2

ทุกค่าตั้งไว้ก่อนรันและเหมือน Phase 3 ไม่มีค่าใดเลือกจากผล test และรายงานทุกรอบที่รัน ผลอยู่ใน `results/reliability/` และ `results/fewshot/` รันด้วย `notebooks/04_reliability_fewshot.ipynb`

### ความน่าเชื่อถือของผลหลัก (MVTec Pill)

รันซ้ำ 5 seed (42, 0, 1, 2, 3) บน split เดิม seed 42 ได้ผลตรงกับ Phase 3 ทุกค่า ช่วงความเชื่อมั่น 95% มาจาก bootstrap ระดับภาพ 2,000 รอบบนผล seed 42 โดย threshold คงที่

| โมเดล | Image AUROC (5 seed) | Recall (5 seed) | Image AUROC ช่วง 95% | Recall ช่วง 95% |
|---|---|---|---|---|
| PatchCore | 0.948 ± 0.003 | 0.853 ± 0.018 | 0.950 [0.912, 0.980] | 0.865 [0.809, 0.915] |
| PaDiM | 0.921 ± 0.015 | 0.384 ± 0.153 | 0.917 [0.864, 0.958] | 0.333 [0.255, 0.412] |

- ผลต่าง Image AUROC ของ PatchCore ลบ PaDiM คือ 0.033 ช่วง 95% [-0.014, 0.083] ช่วงนี้คร่อมศูนย์ จึงยังสรุปไม่ได้ว่า PatchCore ดีกว่า PaDiM ในแง่ Image AUROC บน test set ขนาดนี้
- Recall ของ PaDiM แกว่งตาม seed มาก (0.220 ถึง 0.560) ส่วน PatchCore แกว่งน้อย
- Pixel AUROC และ AU-PRO ของ PatchCore คือ 0.981 ± 0.000 และ 0.940 ± 0.001 ของ PaDiM คือ 0.951 ± 0.004 และ 0.935 ± 0.004 (ไม่มีช่วงความเชื่อมั่นระดับพิกเซล)
- ช่วงรายตำหนิกว้าง เช่น recall ของ color คือ 0.760 [0.560, 0.920] ค่ารายกลุ่มจึงใช้ดูแนวโน้มเท่านั้น

### Few-shot PatchCore

สุ่มภาพปกติ 5 ชุดต่อจำนวนภาพ ตารางแสดง Image AUROC เฉลี่ย ± ส่วนเบี่ยงเบนมาตรฐาน ซึ่งเป็นผลหลักของ few-shot เพราะไม่ขึ้นกับ threshold

| ภาพปกติใน memory bank | MVTec Pill | pillQC |
|---|---|---|
| 1 | 0.820 ± 0.041 | 0.817 ± 0.085 |
| 5 | 0.887 ± 0.019 | 0.910 ± 0.027 |
| 10 | 0.903 ± 0.016 | 0.918 ± 0.015 |
| 25 | 0.927 ± 0.011 | 0.947 ± 0.004 |
| ทั้งหมด (227 / 46) | 0.947 ± 0.003 | 0.957 ± 0.002 |

- ภาพปกติ 25 ภาพให้ Image AUROC ต่ำกว่าการใช้ภาพทั้งหมด 0.020 บน MVTec และ 0.010 บน pillQC ส่วนภาพเดียวให้ผลต่ำและแกว่งมาก
- บน pillQC ค่า recall ที่ threshold จาก validation ต่ำมาก (0.288 ± 0.019 เมื่อใช้ภาพทั้งหมด โดย precision 1.000) เพราะภาพ validation มาจากภาพถ่ายคนละภาพกับ pool จึงได้คะแนนสูงและดัน threshold ขึ้น กติกา threshold เดิมจึงยังใช้ตัดสินปกติหรือผิดปกติกับยาชนิดใหม่ไม่ได้ แม้คะแนนจะเรียงลำดับได้ดี
- บน MVTec ค่า recall ของ few-shot คือ 0.491 (1 ภาพ) ถึง 0.776 (25 ภาพ) เทียบกับ 0.852 เมื่อใช้ภาพทั้งหมด
- ผล few-shot บน MVTec เป็น exploratory เพราะ test set เคยถูกใช้ใน Phase 3 แล้ว

## ข้อจำกัด

- มีผลกับยาเม็ดเพียง 2 ลักษณะ และภาพถ่ายในสภาพควบคุม จึงสรุปไม่ได้ว่าตรวจยาเม็ดทุกรูปทรงได้
- ภาพยาปกติใน test มีเพียง 26 ภาพ และ `pill_type` มี 9 ภาพ ค่ารายกลุ่มจึงแกว่งได้มาก
- validation มีแต่ภาพปกติ จึงวัด recall ของตำหนิไม่ได้
- ช่วงความเชื่อมั่นคิดโดย threshold คงที่ จึงไม่รวมความไม่แน่นอนของ threshold และไม่มีช่วงความเชื่อมั่นของ Pixel AUROC กับ AU-PRO
- few-shot ต้องใช้ภาพปกติเพิ่มสำหรับตั้ง threshold (MVTec 40 ภาพ, pillQC 54 ภาพ) นอกเหนือจากภาพใน memory bank
- pillQC ไม่มี mask จึงไม่มีผลระดับพิกเซล
- ภาพถ่ายต้นฉบับของ pillQC เป็นยาชุดเดิมที่วางใหม่แล้วถ่ายซ้ำ นับได้ราว 28 เม็ดปกติ 15 เม็ดบิ่น และ 31 เม็ดมีคราบ ยาปกติใน test กับใน pool จึงน่าจะเป็นเม็ดเดียวกันที่ถ่ายคนละครั้ง และจำนวนภาพมากกว่าจำนวนเม็ดยาที่เป็นอิสระต่อกัน
- เว็บตรวจ pillQC ได้ทั้งภาพเดี่ยวและภาพหลายเม็ด เดิม threshold ตามกติกาเดิมจับตำหนิได้ราว 25% ในภาพเดี่ยว และ 1.5% ในภาพหลายเม็ดจำลอง หลังให้คะแนนเฉพาะเม็ดยา และเพิ่มยาปกติที่ตัดแบบในฉากเข้า memory bank และไม่หมุนเม็ดยากลมในภาพจำลอง จับได้ 75% ในภาพเดี่ยว และ 74% ในภาพหลายเม็ดจำลอง ผลหลังแก้เป็น exploratory เพราะ test ภาพหลายเม็ดถูกรันหลายรอบ
- ภาพปกติและภาพตำหนิของ pillQC มาจากคนละภาพถ่าย และภาพมีคราบมีเศษดินบนพื้นหลังด้วย heatmap ร้อนทั้งบนคราบและบนเศษดิน คะแนนของกลุ่มมีคราบจึงไม่ได้มาจากตำหนิบนเม็ดยาอย่างเดียว
- สัญญาอนุญาตของ pillQC จำกัดการใช้ร่วมกับผลิตภัณฑ์ของ MathWorks งานนี้ใช้เพื่อการทดลองในรายวิชา และไม่เก็บภาพไว้ใน Git
- ยาชนิดอื่นหรือภาพที่ถ่ายต่างสภาพ มักถูกแจ้งว่าผิดปกติ แม้ไม่มีตำหนิ

## งานต่อยอด: ตำหนิสี

PatchCore พลาดตำหนิ `color` 6 จาก 25 ภาพ ตำหนิกลุ่มนี้เป็นคราบสีที่ยาปกติไม่มี เช่น แดงสด ชมพู เหลือง และน้ำเงิน
จึงเพิ่มตัวตรวจสีที่เก็บสีทุกสีที่พบบนยาปกติใน train ถ้าพบก้อนสีที่ไม่เคยเห็นใหญ่เกิน 20 พิกเซล ก็ถือว่าผิดปกติ
และเปลี่ยนเว็บไปใช้ PatchCore ขนาด 512 ร่วมกับตัวตรวจสี

ผลเป็น exploratory เพราะเลือกวิธีหลังจากเห็นผล test แล้ว รายละเอียดอยู่ใน `README.md` และ `results/phase5/`
