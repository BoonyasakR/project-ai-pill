# AI Pill Anomaly Detection (ภาษาไทย)

ระบบต้นแบบที่ตรวจว่ายาเม็ดปกติหรือมีตำหนิ และชี้ตำแหน่งตำหนิด้วย heatmap โดยเทรนจากภาพยาปกติเท่านั้น

งานนี้เป็นงานวิจัยต้นแบบ ไม่ใช่ระบบรับรองคุณภาพยาจริง ตัวเลขผลทั้งหมดและรายละเอียดการทดลองอยู่ใน [README.md](README.md) (ภาษาอังกฤษ) ส่วนขอบเขตงานอยู่ใน [docs/PROJECT_SCOPE.md](docs/PROJECT_SCOPE.md)

## ปัญหาที่แก้

ในงานตรวจคุณภาพจริง ภาพยาที่มีตำหนิหายาก และตำหนิแบบใหม่อาจไม่เคยเห็นมาก่อน การเทรนโมเดลจำแนกตำหนิแบบปกติจึงทำได้ยาก งานนี้จึงใช้ **anomaly detection** คือให้โมเดลเรียนรู้ว่ายาปกติหน้าตาเป็นอย่างไร แล้วถือว่าอะไรที่ต่างจากยาปกติมากคือตำหนิ

## หลักการทำงาน

### PatchCore (โมเดลหลัก)

1. ส่งภาพยาปกติเข้า CNN ที่เทรนมาแล้ว (backbone) เพื่อดึง feature ของแต่ละ patch เล็ก ๆ ในภาพ
2. เก็บ feature ของ patch จากยาปกติทั้งหมดไว้ใน **memory bank** แล้วคัดให้เหลือส่วนเล็ก ๆ ที่ครอบคลุมพอ (coreset 1%) เพื่อให้ค้นหาเร็ว
3. ตอนตรวจ แต่ละ patch ของภาพใหม่จะถูกเทียบกับ patch ที่ใกล้ที่สุดใน memory bank ถ้าห่างมาก แปลว่า patch นั้นไม่เหมือนยาปกติ
4. ระยะห่างของทุก patch รวมกันเป็น **heatmap** ส่วนค่าสูงสุดคือ **คะแนนของภาพ**
5. ถ้าคะแนนเกิน **threshold** ถือว่ายาผิดปกติ threshold ตั้งที่เปอร์เซ็นไทล์ 99 ของคะแนนยาปกติในชุด validation ไม่ได้ดูชุด test

PaDiM ใช้เป็น baseline เพื่อเปรียบเทียบ โดยจำค่าเฉลี่ยและความแปรปรวนของ feature ในแต่ละตำแหน่งแทนการเก็บทุก patch

### Colour check (เสริมสำหรับ MVTec Pill)

PatchCore พลาดคราบสีเล็ก ๆ บางจุด เช่น สีชมพู เหลือง หรือฟ้า เพราะยาปกติมีจุดสีแดงอยู่แล้ว จึงเพิ่มตารางสีที่เคยเห็นบนยาปกติทั้ง 227 เม็ด (histogram ในระบบสี Lab) ถ้าเจอก้อนสีที่ไม่เคยเห็นใหญ่กว่า 20 พิกเซล ก็ถือว่าผิดปกติ ผลคือจับตำหนิสีได้ 96% โดยไม่เพิ่ม false positive

### ยาหลายเม็ดในภาพเดียว

ถ้าภาพมียาหลายเม็ดวางไม่ทับกันบนพื้นสีเข้ม ระบบจะแยกแต่ละเม็ดออกมา หมุนและจัดขนาดให้เหมือนภาพที่ใช้เทรน แล้วตรวจทีละเม็ดด้วยโมเดลเดิม ส่วนนี้ทดสอบบนภาพจำลองที่ตัดแปะเท่านั้น ยังไม่ใช่ผลกับภาพถ่ายจริง

## ชุดข้อมูล

| ชุดข้อมูล | ใช้ทำอะไร | หมายเหตุ |
|---|---|---|
| MVTec AD หมวด Pill | ผลหลัก มี mask ตำแหน่งตำหนิ 7 ประเภท | train 227 / validation 40 / test 167 ภาพ |
| pillQC | ยาเม็ดชนิดที่สอง (การทดลองรอบ 2) | มีแค่ label ระดับภาพ แบ่งชุดตามภาพถ่ายต้นฉบับ |

ภาพไม่ได้เก็บใน repo นี้ ต้องดาวน์โหลดเอง ลิงก์อยู่ใน [README.md](README.md#datasets)

## ผลโดยสรุป

| โมเดล (MVTec Pill) | Image AUROC | Pixel AUROC | Precision | Recall | F1 |
|---|---|---|---|---|---|
| PatchCore (ผลหลัก) | 0.950 | 0.981 | 0.984 | 0.865 | 0.921 |
| PaDiM (baseline) | 0.917 | 0.952 | 1.000 | 0.333 | 0.500 |
| PatchCore 512 + colour check (ที่ใช้ในเว็บ) | 0.979 | – | 0.992 | 0.915 | 0.952 |

- PatchCore จับตำหนิได้มากกว่า PaDiM ชัดเจน (recall 0.87 กับ 0.33) แต่ช่วงความเชื่อมั่น 95% ของ Image AUROC ยังซ้อนกัน จึงสรุปไม่ได้ว่าเรียงลำดับภาพดีกว่า
- ตำหนิที่ยากที่สุดคือรอยร้าว (crack) จางที่ขอบเม็ด
- pillQC แบบเม็ดเดียวได้ Image AUROC 0.990 และ recall 0.751 ที่ precision 1.000
- ผลของโมเดล 512 และ colour check เลือกหลังเห็นชุด test แล้ว จึงนับเป็นผลเชิงสำรวจ

## โครงสร้างโปรเจกต์

| โฟลเดอร์ | เนื้อหา |
|---|---|
| `notebooks/` | Colab notebook: เตรียมข้อมูล, เทรนและประเมิน, การทดลอง, ความน่าเชื่อถือและ few-shot |
| `src/` | สคริปต์เทรน PatchCore, วัดผล, สร้างภาพยาหลายเม็ดจำลอง, สร้างโมเดล pillQC |
| `splits/` | ไฟล์แบ่ง train/validation ที่ล็อกไว้ (seed 42) |

| `frontend/` | เว็บ React: อัปโหลดภาพ, ผลการตรวจ, เปรียบเทียบโมเดล, ผลการทดลอง |
| `tests/` | unit test |
| `docs/` | รายงาน สไลด์ ขอบเขตงาน และบันทึกการอัปเดต |

## วิธีรันเว็บ

ไฟล์โมเดลที่ใช้งานอยู่ 3 ไฟล์ใน `models/` เก็บผ่าน Git LFS (ต้องติดตั้ง Git LFS ก่อน clone หรือ pull เพื่อดาวน์โหลดไฟล์จริง) หากต้องการเทรนใหม่ ให้วางภาพ MVTec Pill ไว้ที่ `data/mvtec/pill/` แล้วใช้คำสั่งด้านล่าง ใช้เวลาประมาณ 15 ถึง 30 นาทีบน Apple M3

```bash
python3.12 -m venv backend/.venv
```

```bash
backend/.venv/bin/pip install -r backend/requirements.txt
```

```bash
backend/.venv/bin/python src/train_patchcore.py --size 512 --coreset 0.01 --out models/patchcore_pill_512.pt
```

```bash
backend/.venv/bin/python -m uvicorn app:app --app-dir backend --port 8000
```

ถ้าจะตรวจยา pillQC ด้วย ให้วางภาพไว้ที่ `data/pillqc/` แล้วสร้าง memory bank ก่อน จากนั้นเลือกชนิดยาในหน้าอัปโหลด

```bash
backend/.venv/bin/python src/build_pillqc_model.py --root data/pillqc
```

เปิดอีก terminal แล้วรัน frontend จากนั้นเปิด http://localhost:5173

```bash
cd frontend && npm install && npm run dev
```

API หลักของ backend:

- `GET /api/health` ตรวจว่ามีไฟล์โมเดลหรือไม่
- `GET /api/results` ผลการทดลองที่บันทึกไว้
- `POST /api/inspect` ส่งภาพ (และชนิดยา `mvtec` หรือ `pillqc`) แล้วได้ผลปกติ/ผิดปกติ คะแนน และ heatmap

## ข้อจำกัด

- ผู้ใช้ต้องเลือกชนิดยาเอง ระบบไม่ระบุชนิดยาอัตโนมัติ และแต่ละชนิดต้องมี memory bank กับ threshold ของตัวเอง
- บอกได้ว่าผิดปกติตรงไหน แต่ไม่บอกว่าเป็นตำหนิประเภทใด
- ไม่รองรับยาที่วางทับกัน พื้นหลังสว่าง แคปซูล หรือยาในแผง
- ผลยาหลายเม็ดมาจากภาพจำลอง ภาพถ่ายจริงมีเงาและแสงไม่สม่ำเสมอ ซึ่งยังไม่ได้ทดสอบ
- เม็ดยาที่เล็กกว่า 180 พิกเซลอาจถูกแจ้งผิดว่าผิดปกติ
